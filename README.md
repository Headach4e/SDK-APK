# Лабораторная работа: Статический анализ и детекция SDK в Android-приложениях из RuStore

## 📌 Цель работы
Освоить методы статического анализа мобильного ПО для Android, научиться декомпилировать APK-файлы, выделять сигнатуры (признаки) сторонних SDK и формировать структуру базы знаний SDK, используемых на российском рынке.

---

## 🛠 Инструментарий
Для выполнения работы вам понадобятся:
- **JADX / JADX-GUI** — декомпиляция DEX-файлов в Java/Kotlin код ([GitHub JADX](https://github.com/skylot/jadx)).
- **Apktool** — декодирование ресурсов и файла `AndroidManifest.xml` ([Apktool](https://apktool.org/)).
- **Python 3.10+** и `pytest` — для локальной проверки решения автотестами.
- **Любой ZIP-архиватор** — для быстрого разбора структуры `.apk` (`lib/`, `assets/`).

## 📋 Задания

### Задание 1. Формирование базы знаний SDK (`sdk_database.json`)
Заполните файл `sdk_database.json` (на основе шаблона `templates/sdk_database_template.json`).
База должна содержать **не менее 15 различных SDK**, широко используемых в РФ (RuStore SDK, AppMetrica, Yandex MapKit, VK ID, SberPay, Tinkoff Acquiring, MyTracker, Huawei HMS Push и др.).

Для каждого SDK заполняются поля:
- `id`: уникальный строковый идентификатор (например, `rustore-push`).
- `name`: официальное название SDK.
- `category`: одна из категорий (`analytics`, `push`, `payments`, `maps`, `auth`, `ads`, `crash_reporting`).
- `package_prefixes`: список префиксов Java-пакетов (например, `["ru.rustore.sdk.push"]`).
- `manifest_signatures`: ключевые записи в `AndroidManifest.xml` (Services, Receivers, `<meta-data>`).
- `native_libs`: список файлов нативных библиотек `.so` (если есть, иначе пустой список `[]`).
- `official_repo`: ссылка на Maven/GitHub репозиторий.

---

### Задание 2. Декомпиляция и анализ 10 APK из RuStore (`apps_analysis.csv`)
1. Скачайте **10 различных `.apk` файлов** из каталога [RuStore](https://www.rustore.ru/) из развлекательных и прикладных категорий (Финансы, Покупки, Навигация, Инструменты и др.).
2. Проведите декомпиляцию и анализ каждого приложения.
3. Заполните отчетный файл `apps_analysis.csv` (на основе шаблона `templates/apps_analysis_template.csv`).

Для каждого приложения указываются:
- `app_name`: название приложения.
- `package_name`: имя пакета Android (например, `ru.sberbankmobile`).
- `category`: категория в RuStore.
- `detected_sdks`: список обнаруженных SDK IDs через запятую (соответствующих `id` из `sdk_database.json`).
- `detection_evidence`: краткое описание найденных признаков (пакеты, теги манифеста, `.so`-файлы).

---

### Задание 3. Аналитический отчет (`REPORT.md`)
Подготовьте краткий отчет в файле `REPORT.md`, отражающий:
1. Сводную статистику по обнаруженным SDK (какие SDK наиболее популярны в вашей выборке).
2. Анализ импортозамещения (соотношение отечественных SDK и зарубежных аналогов, например RuStore Push vs FCM, AppMetrica vs Firebase).
3. Основные сложности при детекции (обфускация кода ProGuard/R8, динамическая загрузка и т.д.).


## 🧪 Локальный запуск автотестов
Перед отправкой работы в GitHub убедитесь, что автотесты проходят локально:
```bash

```

При каждом push или pull request в GitHub автоматически запускается GitHub Actions workflow, который проверяет комплектность и корректность структуры данных.
